what gets stored where
MinIO · S3 storage
File bytes
Holds the actual file content — nothing else.
  • Stores binary objects (streaming up to 100MB) no full buffering in memory
  • Isolates services by bucket {service}-{env} · cross-service access blocked in API
  • Indexes by time-prefixed key yyyy/MM/dd/HH/mm/name · fast range scans
  • Stores each unique hash once dedup · re-uploads of same bytes reuse object
  • Survives blips via Polly circuit breaker + 3x retry with jitter
SQL Server · metadata
Files & references
Source of truth for ownership, lifecycle, and audit.
  • File — one row per unique content hash, size, MIME, status (Pending → Confirmed → Deleted), TTL
  • FileReference — one row per service that owns it enables sharing: 3 services, 1 object, 3 refs
  • Tracks reference count for cleanup file kept until all refs released + 7-day grace
  • AuditLog — every call recorded correlationId, serviceId, duration, status
  • Monthly partitioned on CreatedAt fast queries · easy archival / purge
Redis · coordination
Locks & leader
Keeps multiple API instances from stepping on each other.
  • Dedup lock during upload dedup:{hash} · 5s TTL · prevents race on same content
  • Leader election for cleanup worker cleanup:leader · 70 min TTL · only one instance sweeps
  • Degrades gracefully when down upload still succeeds · logs warning, skips dedup
  • Health-checked on readiness probe /health/ready returns 503 if Redis unreachable
